## 1.5-A

### 1. 이미지 붙여넣기 (Ctrl+V)
- 클립보드의 PNG/JPG를 업로드와 같은 경로(`request`)로 불러온다. 편집 중이면 기존의 "현재 작업이 사라집니다" 확인을 그대로 쓴다.
- PNG/JPG가 아닌 이미지는 일반 업로드와 같은 오류를 보여준다(조용히 무시하지 않는다).
- 입력창에 포커스가 있으면 붙여넣기를 가로채지 않는다.
- 이미지는 **클립보드에 이미지가 있을 때만** 붙여넣는다. 이미지가 없으면 앱 내부에 복사해 둔 레이어가 있어도 아무 일도 없다.
- 클립보드의 이미지가 Ctrl+C로 복사한 레이어의 그림(해시가 같음)이면 레이어로 붙여넣고, 그 밖의 이미지는 새 이미지로 불러온다(아래 3번).

### 2. 배경 채움 개선
- (a) **가까운 링과 먼 링 비교**: 가까운 링(기본 3px)과 먼 링(12~24px)이 각각 한 가지 색인데 8 이상 다르면 자동 채움 대신 색을 묻는다. 먼 링이 이미 여러 색(다른 카드의 가장자리를 가로지름)이면 판단 근거가 못 되므로 쓰지 않는다. 먼 링을 만들 공간이 없으면(이미지 가장자리) 가까운 링만으로 판단한다.
- (b) **제안색**: 색 선택 창의 시작 색을 가장 바깥 띠(32~48px)에서 뽑는다. 그 띠가 여러 색이면 먼 링, 그것도 아니면 가까운 링 순으로 물러난다.
- 임계값: `NEAR_FAR_TOLERANCE = 8`, 먼 링 12~24px, 제안 띠 32~48px, 띠의 최소 픽셀 수 40. 기존 값(링 3px, 허용오차 12, 이상치 20%, 지배색 50%)은 그대로다.

`tests/fixtures/realistic-capture.png`(그라데이션 배경, 그림자 있는 카드, 버튼, 헤더) 기준 전/후:

| 선택 영역 | 전 | 후 |
|---|---|---|
| 카드를 정확히 선택 | 묻는다, 제안 `#daddee`(그림자 섞임) | 묻는다, 제안 `#e8edfb`(카드 뒤 실제 배경) |
| 카드 + 여백 40px | 자동 `#e6eafa` | 자동 `#e6eafa` |
| 카드 안의 버튼 | 자동 `#ffffff` | 자동 `#ffffff` |
| 카드 안의 썸네일 | 자동 `#ffffff` | 자동 `#ffffff` |
| 카드 안의 텍스트 막대 | 자동 `#ffffff` | 자동 `#ffffff` |
| 헤더(이미지 위쪽 가장자리) | **자동 `#d7dded`(그림자색의 회색 띠)** | **묻는다**(가까운/먼 링 차이 16), 제안 `#e3e9fa` |
| 넓은 차트 카드를 정확히 선택 | 묻는다, 제안 `#d1daec` | 묻는다, 제안 `#d9e2f9` |

카드 중앙 아래 실제 배경 그라데이션과 제안색의 차이(채널 최대값)는 전 19 → 후 4로 줄었다. 헤더는 링 폭 1·3·5 모두 묻는다(차이 18·16·13).

### 3. 단축키
`Ctrl+Z`(실행 취소) · `Ctrl+Shift+Z` / `Ctrl+Y`(다시 실행) · `Delete`(삭제) · `Ctrl+D`(복제) · `Ctrl+C` / `Ctrl+V`(레이어 복사·붙여넣기, 앱 내부만) · `V`(선택) · `H`(이동) · `R`(영역 추출). macOS의 ⌘도 같다.
- 입력창에 포커스가 있거나 모달 대화상자가 열려 있으면 동작하지 않는다.
- `Delete` · `Ctrl+D` · `Ctrl+C`는 키를 누르고 있어도 반복하지 않는다. `Ctrl+Z`는 반복한다.
- `Ctrl+D`는 브라우저의 즐겨찾기 단축키라서 항상 가로챈다.
- 레이어 붙여넣기는 원본 위치에서 (+16, +16)씩, 반복할수록 한 칸씩 더 밀려 나가 서로 가리지 않는다.
- **레이어 복사·붙여넣기는 시스템 클립보드를 통한다.** Ctrl+C는 그 레이어의 비트맵을 PNG로 클립보드에 쓰고, 앱은 그 그림의 해시(크기+RGBA 픽셀의 SHA-256. 파일 바이트가 아니므로 클립보드가 다시 인코딩해 돌려줘도 같다)와 레이어 정보를 기억한다. Ctrl+V는 클립보드에 그림이 있을 때만 동작한다: 해시가 같으면 레이어로, 다르면 새 이미지로(교체 확인 포함) 불러오고, 그림이 없으면 앱 내부 복사본이 있어도 아무 일도 없다.
- 창을 벗어났다 돌아와도 복사는 유지된다(이전의 "창이 포커스를 잃으면 복사본을 버린다" 규칙은 폐기). 다른 곳에서 새 그림을 복사하면 해시가 달라져 새 이미지로 불러온다.
- 클립보드 쓰기가 막히면(권한 없음, 클립보드 API 없음, 이미지 복사 미지원, 그 밖의 오류) 작업 영역 위의 안내 줄에 "레이어를 복사하지 못했습니다. + 원인"을 보여 주고 복사본은 기억하지 않는다(붙여넣어도 맞을 그림이 없기 때문). 안내는 닫을 수 있고, 다음 복사가 성공하면 지워진다.
- 툴팁에 단축키를 적었다(예: "실행 취소 (Ctrl+Z)").

### 4. 레이어 잠금·숨김·이름 변경
- 레이어 패널에 눈(숨김)·자물쇠(잠금) 버튼, 속성 패널에 이름 입력.
- **숨김**: 화면과 PNG 모두에서 제외. 캔버스에서 집을 수 없지만 목록에서는 선택된다.
- **잠금**: 이동·삭제·크기 조절·회전 불가. 선택·이름 변경·복사·앞뒤 순서·숨김은 가능. 잠긴 레이어의 선택 윤곽은 점선이다.
- 복제·붙여넣기한 레이어는 보이고 잠기지 않은 새 레이어다.
- 이름: Enter 또는 포커스 이동으로 확정(1단계), Escape로 취소, 빈 이름은 거부, 최대 60자. 모든 변경은 Undo 1단계.
- 규칙은 스토어에서 강제한다. 버튼을 비활성으로 두는 것과 별개로 단축키·드래그도 못 뚫는다.

## 1.5-B

### 5. 레이어 크기 조절·회전, 스키마 v2
- **조작**: 선택한 레이어에 Konva Transformer 핸들이 붙는다. 모서리 점은 비율 유지로 크기를, 위쪽 둥근 점은 회전을 바꾼다. 속성 패널에 변환된 너비·높이, 회전(°), 크기 배율이 나오고 "크기·회전 초기화" 버튼이 있다. 한 번 끌면 Undo 1단계다.
- **모델**: 비트맵 점 `p`는 `T(x, y) · R(rotation) · S(scaleX, scaleY) · p`로 프레임 픽셀에 놓인다. `(x, y)`는 비트맵 왼쪽 위 모서리이자 회전 중심이며 rotation은 시계 방향 도(°)다. 화면과 PNG가 같은 식을 쓴다.
- **저장 값**: `x`·`y` 소수 2자리, scale 소수 4자리, rotation 소수 2자리로 반올림, scale은 부호를 유지하되 0.05~50으로 제한, rotation은 (-180, 180]로 정규화.
- **PNG**: 이동만 한 레이어는 기존의 픽셀 단위 정확한 복사 경로다. 크기·회전이 있으면 출력 픽셀 중심을 비트맵으로 역변환해 쌍선형(premultiplied) 샘플링하고, **가장자리는 안티앨리어싱**한다: 출력 픽셀이 레이어에 덮인 비율(4×4 표본)을 알파에 곱하므로, 가장자리를 지나는 픽셀은 레이어 자신의 색에 반투명이 된다(어두워지거나 섞이지 않는다). 픽셀 네 모서리가 모두 안쪽이면 표본 없이 100%, 모두 바깥쪽이면 건너뛰어, 비용은 가장자리에만 든다. 90°의 배수는 `cos/sin`을 정확한 값으로 써서 픽셀이 한 칸의 오차도 없이 떨어진다. 출력 크기 규칙(원본 크기)은 그대로다.
- **이전 결과와의 동일성**: 가장자리가 픽셀 경계에 정확히 맞는 경우(회전 0·90·180·270°·360°, -90°, 정수 위치, 정수 배율·0.5배, 반전)는 걸치는 픽셀이 없어서 안티앨리어싱 이전 알고리즘과 **바이트 단위로 같다**. 이전 알고리즘을 테스트 안에 오라클로 두고 15가지 구성을 비교한다(불투명도, 프레임 밖으로 나간 경우 포함).
- **스키마 version 2**: `transform.scaleX/scaleY/rotation`이 리터럴 `1/1/0`에서 숫자로 바뀐다. `migrate.ts`의 1→2 단계는 값을 그대로 두고, 빠진 값만 `1/1/0`으로 채운다. Phase 1 빌드가 실제로 저장한 파일(`tests/fixtures/project-v1.slc.json`)이 그대로 열리고 version 2로 저장된다.

### 6. 원본/수정본 비교
- 상단 바에 `수정본 | 원본 | 나란히` 전환. **원본**은 업로드한 그대로를 같은 자리에, **나란히**는 왼쪽 원본·오른쪽 수정본을 둘 다 화면에 맞춰 보여준다. 나란히를 나가면 이전 보기(zoom/pan)로 돌아간다.
- 비교 중에는 **편집이 모두 거부된다**(스토어에서 강제: 추출·이동·복제·붙여넣기·삭제·순서·숨김·잠금·이름·크기·회전·패치 색). 패널의 편집 버튼은 비활성이 된다. 선택·복사·도구·zoom/pan·Undo/Redo는 허용한다.
- PNG와 프로젝트 저장은 어떤 보기에서든 **수정본**이다. 비교 중 내보내기 대화상자에 그 사실을 적었다.
- 새 이미지를 올리거나 프로젝트를 열면 비교는 꺼진다.

## 이어서 추가: 임시저장 (자동 복원)
- **저장**: 프로젝트가 바뀌면 800ms 뒤에 IndexedDB에 저장한다(연속 편집은 한 번으로 합쳐진다. 저장 중에 또 바뀌면 한 번 더). 기록은 `autosave` 스토어의 `{format, version: 1, savedAt, project}` JSON이고, 이미지는 기존 `blobs` 스토어에 Blob으로 둔다. Blob URL도 base64도 기록에 넣지 않는다. Blob을 먼저, 기록을 나중에 써서 기록이 없는 이미지를 가리키는 일이 없다. 페이지가 숨겨지거나 닫힐 때(`visibilitychange`, `pagehide`)는 기다리지 않고 바로 저장한다. 저장 실패는 푸터와 경고 줄에 이유와 함께 보인다.
- **DB 버전**: 같은 DB(`screenshot-layer-canvas`)가 버전 2가 되어 `autosave` 스토어가 추가된다. 이전 버전의 DB는 열 때 업그레이드된다.
- **복원**: 앱을 열었을 때 임시저장본이 있으면 "이전 작업을 복원할까요?"(이름·화면 크기·레이어 수·저장 시각)를 묻는다. **복원** 또는 **버리기**를 반드시 골라야 하며(Esc로 닫히지 않는다), 답하기 전에는 저장본을 덮어쓰지 않는다. 복원하면 위치·순서·패치·잠금·숨김·이름·크기·회전·화면 위치가 그대로 돌아오고 히스토리는 비어 있다. **`pruneBlobStore`는 복원 직후에만** 부른다.
- **버리기**: 저장본과 그 Blob을 지운다(`blobs.clear()`). 이것은 prune이 아니다: 지금 이 탭만이 쓸 수 있고 히스토리가 비어 있어서 다른 어디서도 그 Blob을 가리키지 않는다.
- **손상된 저장본**: 형식이 틀리거나, 프로젝트 검증에 실패하거나, 필요한 이미지가 없으면 복원을 제안하지 않고 "이전 임시저장본이 손상되어 … 지웠습니다"를 알리고 지운다(편집기는 빈 상태). 이미지는 있는데 그림으로 읽을 수 없으면 복원을 눌렀을 때 "복원하지 못했습니다"를 알리고 지운 뒤 편집기를 빈 상태로 둔다.
- **여러 탭**: Web Locks(`navigator.locks`)로 **소유 탭 하나만** 쓴다. 다른 탭은 자동 저장을 끄고("이 탭은 자동 저장하지 않습니다" 안내 줄과 푸터 표시) 복원 제안도 하지 않는다. 그 탭의 Blob 저장소는 **메모리**라서, 그 탭에서 프로젝트를 열거나 저장하는 일(`blobs.clear()`·prune을 하는 경로)이 소유 탭의 Blob을 지울 수 없다. 소유 탭이 닫히면 대기 중인 탭이 이어받고, 그 탭에는 닫힌 탭의 작업을 복원할지 묻는다(지금 열려 있는 화면이 있으면 "대체됩니다"를 함께 알린다). Web Locks가 없는 브라우저에서는 탭이 하나뿐이라고 가정한다.
- **새 이미지·프로젝트 열기와의 관계 (결정)**: 임시저장은 항상 *지금의* 프로젝트를 따라간다. 새 이미지로 시작하거나 프로젝트 파일을 열면 다음 저장이 이전 기록을 덮어쓴다("마지막 프로젝트가 남는다"). 이전 기록을 따로 지우거나 prune하지 않는다. 대신 그 사이에 쓰이지 않는 Blob이 IndexedDB에 남을 수 있고, 다음 복원 때 prune으로 정리된다. 복원을 묻는 동안에는 모달이라 새 이미지를 시작할 수 없다.
- 이 일을 하면서 찾아 고친 것: 안내 줄이 `display:none`일 때 CSS grid 행이 밀려 작업 영역이 638px에서 277px로 쪼그라드는 레이아웃 오류(flex 열로 바꾸고 크기를 직접 재는 테스트를 추가). 캔버스를 끌다가 줌 도구막대의 "−"가 글자로 선택되어 Ctrl+C가 막히던 문제(편집기 UI를 선택 불가로).

| `panels` "none of them is editable" | 이제 이름만 편집 가능: "입력창 0개" → "이름 입력창 1개, X·Y·너비·높이는 텍스트" |
| `handoff`·`transform`·`panels`·`lock-hide-rename`의 `page.reload()` 4곳 | 새로고침 뒤에 임시저장 복원 질문이 뜨므로 `reloadAndDiscard`(질문에 "버리기")로 바꿈. 이전에는 새로고침하면 빈 상태였다 |
| `app` "no hairline … old spot" | 옮긴 레이어가 선택된 채라 회전 핸들이 옛 자리에 걸림 → 스캔 전에 선택 해제 |

앱 동작이 의도대로 바뀐 것(툴팁, 이름 입력창, 핸들이 보이는 것)을 테스트가 따라간 것이며, 어느 것도 기대값을 약하게 만들지 않았다. 나머지 Phase 1 E2E는 수정 없이 통과한다.

## 테스트와 변이 검사

최종 결과는 아래 "최종 검증"에 있다. 일부러 코드를 망가뜨려 테스트가 실패하는 것을 확인한 항목이다(확인 후 원복).

- 1→2 마이그레이션 제거 → v1 파일 테스트(단위·E2E) 실패
- 내보내기의 회전 방향 뒤집기 / 모델의 회전 부호 뒤집기 → 합성·기하 테스트, E2E 실패
- PNG가 숨김을 무시 → 숨김 테스트 실패
- 잠금 가드 제거(이동·삭제) → 잠금 테스트 실패
- 비교 중 편집 차단 제거 → 단위 6개, E2E 2개 실패
- 근/원 링 비교 끄기, 제안색을 가까운 링으로 되돌리기 → 샘플링 테스트 실패
- 입력창 가드, 모달 가드 제거 → 단축키 E2E 실패
- 해시 비교를 항상 참 / 항상 거짓으로, "그림 없으면 아무것도 안 함" 제거, 클립보드에 쓰지 않기 → 클립보드 단위·E2E 실패
- 소유가 아닌 탭도 공유 DB를 쓰게 하기 → 다중 탭 단위 4개·E2E 4개 실패 ("다른 탭이 첫 탭의 Blob을 못 지운다" 테스트가 처음엔 이 변이를 놓쳐서, 소유권이 바뀌지 않는 것을 확인한 뒤 진행하도록 보강)
- 답하기 전 저장본 덮어쓰기 허용, 복원 후 prune 생략, 저장 때마다 prune, 어디서도 기록을 지우지 않기 → 임시저장 단위·E2E 실패
- 안내 줄을 `display:none`으로 되돌리기(원래 레이아웃 오류) → 레이아웃 측정 테스트 3개 실패
- 안티앨리어싱 끄기, 샘플링 가중치 오류, 가장자리 픽셀 샘플링 생략 → 안티앨리어싱·바이트 동일성 테스트(단위·E2E) 실패
- 배지를 다시 위쪽에 두기 → 겹침 테스트 실패

테스트가 잡아 고친 실제 버그: Escape가 이름을 되돌리지 않고 저장함(`blur`가 낡은 값으로 확정). 스크린샷으로 찾아 고친 것: 나란히 보기의 안내 배지가 줌 도구막대에 가려짐, 크기 배율 값이 잘림.

## 한계와 알려진 점

- 화면은 zoom 100% 이상에서 가장 가까운 점 샘플링, PNG는 쌍선형이라 크기를 바꾼 레이어는 확대해서 보면 화면이 더 거칠다. 위치·모양은 같다.
- 크기 조절은 반전(flip)을 막았다. 스키마는 음수 scale을 받아 주지만 UI는 만들지 않는다.
- 회전 핸들의 눈금 스냅은 없다(정렬 스냅은 범위 밖).
- 헤더처럼 이미지 가장자리에 닿아 가까운 링이 한쪽뿐이어도 먼 링은 그 쪽에서 구한다. 반대로 12~24px 띠를 만들 공간이 없으면 비교를 건너뛰고 가까운 링만 쓴다.
- 레이어는 마우스로만 옮긴다(키보드 이동 없음).
- 임시저장: 프로젝트 파일을 열면 IndexedDB의 Blob 저장소를 비우고 다시 쓰므로, 새 프로젝트의 첫 저장(약 1초) 전에 탭이 죽으면 이전 기록이 가리키는 Blob이 없어 "손상"으로 처리된다(이전 프로젝트는 사용자가 일부러 대체한 것이다).
- 임시저장: 새 이미지·프로젝트 열기가 남긴 쓰이지 않는 Blob은 다음 복원 때까지 IndexedDB에 남는다(복원 직후에만 prune하는 규칙의 결과).
- 임시저장: 권한 거부, 용량 초과 같은 저장 실패는 보이지만, 브라우저가 IndexedDB 자체를 지우는 경우(사이트 데이터 삭제, 일부 사생활 보호 모드)는 막을 수 없다.
- 다중 탭은 같은 브라우저 프로필 안에서만 조정된다(다른 브라우저·프로필은 서로 다른 IndexedDB다). Web Locks가 없는 브라우저는 탭이 하나뿐이라고 가정한다.
- 클립보드: 레이어 복사의 쓰기 권한 거부는 "쓰기가 거부됐다"를 흉내 낸 테스트로만 확인했다(헤드리스에서는 사용자 제스처가 있는 쓰기가 허용된다). 실제 브라우저의 권한 거부 화면은 확인하지 못했다.
- Chromium 외 브라우저, 터치 입력, 실제 GPU 환경은 확인하지 못했다.
